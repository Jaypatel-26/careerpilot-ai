# Signed-in account dashboard and navigation

The previous `/dashboard` always rendered sample data, even when the user was signed in. This update preserves the guest demo but renders a private account dashboard after login or signup. The dashboard uses the authenticated backend; no demo profile, interview score or progress is substituted when data is absent or an API request fails.

## What changed

- After login/signup, the user lands on `/dashboard`. A signed-in user sees their actual account name, profile target role, interview totals and completed counts, the average of saved interview-report scores, the latest five interviews, a chart of up to ten recent report scores, saved job/match counts, resume-report count and career-roadmap progress/next task. Empty values are clearly shown; an unavailable API shows an error with retry, not fake numbers.
- New `GET /api/v1/dashboard` is JWT-protected, owner-filtered and marked `Cache-Control: no-store`. Report scores are the saved 0–100 values. Counts are based on existing rows; recent items and chart are limited to five and ten. Current roadmap progress is a task-completion estimate, not proof of mastery. No new tables, database migration, or Gemini calls are needed.
- When signed in, sidebar links and account settings use account-backed features. Demo URLs redirect signed-in visitors to their matching account page. The sample question bank has no account-backed equivalent, so its URL goes to real AI interview setup; it is not portrayed as a saved personal question bank. Original guest demo data remains in the browser and is not imported as account data. To return to the guest demo, sign out, then use Explore demo. Session storage remains per tab as before; another tab may require login.
- Account pages no longer offer links to demo resume, demo jobs or demo interview history. Direct access to the landing page while signed in goes to the account dashboard. Account settings offers profile and sign-out; the old demo-only settings are retained for guests. Password recovery and account deletion remain unavailable.
- The fixed Phase 6 roadmap Gemini schema and removed resume notice from the previous delivery are preserved. Earlier Phase 1–6 files and migrations remain; no Supabase or Adzuna is introduced. If the database has records from the old optional Adzuna experiment, this version does not remove them automatically.

## Deploy on Render

1. Back up the Neon database as usual. No new migration is required for this update, but existing migrations must remain in GitHub.
2. Unzip the complete project and upload the **contents** of `careerpilot-neon-render` at your existing GitHub repository root. Ensure `backend/app/api/dashboard.py`, `backend/app/main.py`, `src/features/dashboard/AccountDashboard.tsx`, `src/main.tsx`, and `src/style.css` are at those exact paths. Commit the changes; do not upload keys, local databases, `node_modules`, `.venv`, or real `.env` files.
3. Deploy the **backend first**, then the **frontend**, from the same new commit. This update needs both: an older backend does not have `/api/v1/dashboard` and will produce an error instead of account statistics. Keep the existing Render environment values, Neon URLs, JWT, Gemini and CORS settings and start command unchanged. Do not change `alembic_version` or delete tables. Verify backend deployment successfully starts, then frontend deployment completes.
4. Refresh the website and sign in. Check the dashboard shows your own name and saved activity, and visit profile, interviews, resume, jobs and roadmap. Test a separate account; it must not see the first account's records. Sign out and check Explore demo. If an old frontend is cached, hard refresh the browser; do not share secrets or resume contents in screenshots/logs.
